# Q: لماذا تتلف طباعة كل الأصناف بينما تطبع حركات المخزن الأخرى سليمة؟

## Answer

Expanded from original query via graph vocab: [stock, balance, print, receipt, thermal, printer, bluetooth, png, height, width, all, items]. DashboardScreen sends DashboardSuccess.allItems through StockBalanceReceiptMapper to one ThermalReceiptContent. ReceiptController.getImageBytes rasterizes the entire long widget as one 576-dot PNG. BluetoothPrinterRepository calls printImageSingle once. flutter_bluetooth_printer 2.24.0 encodes the whole image as one ESC/POS raster payload, and its Android implementation writes the full byte array in one OutputStream.write call rather than pacing bounded chunks. This exceeds the practical 64KB XP-P802A input buffer for a long inventory report, so bytes are dropped or misinterpreted and the paper shows corrupted characters or duplicated starts. Short movement receipts remain under the problematic payload size. Root fix: keep one logical receipt but split raster data into safe vertical slices and send sequentially with real chunk pacing; add a long-receipt regression test and physical XP-P802A acceptance.
