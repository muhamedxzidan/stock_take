## Answer

Expanded via graph vocabulary: [return, returns, warehouse, adjustment, stock, screen, form, route, navigation, quantity, condition, draft]. Confirmed both routes and screens already exist but were hidden from simplified navigation. WarehouseReturnScreen is explicitly UI-only; its form builds WarehouseReturnDraft and only shows a notice unless an onSubmit callback is supplied. StockAdjustmentScreen calls TransactionsCubit.createAdjustmentTransaction, but that only creates a one-item in-memory transaction log and does not update DashboardRepository stock. Recommended simplest worker UI: keep three main navigation destinations and expose two secondary operation cards from New Movement: Warehouse Return and Stocktake. Rework Return to sequential multi-item selection with quantity and condition per item, and Stocktake to sequential item counts showing system quantity, actual cartons/pieces, and difference. Business rules need approval before logic: only ready-for-stock returns should increase available stock; damaged or inspection items should remain quarantined, and stocktake should set stock to the confirmed actual quantity.
